## 1. 目标与范围

发起审批时展示将要发起的流程图；我的待办、我的已办、我的流程查看详情时展示该实例的实际流程图和运行状态。三个正式实例详情入口沿用同一个 `DetailDrawer.vue`，避免各页面实现不同的图和访问规则。仓库中另有旧的 `approval/TaskPanel.vue` 调用该抽屉，但当前没有页面挂载它，不能算作第四个可操作入口。

本期不改 Warm-Flow 版本、第三方 JAR、流程定义与实例表结构，不以创建临时流程实例的方式生成发起前预览。审批表单快照、办理资格和旧实例详情的现有语义保持不变。

## 2. 已核对的现状与关键区别

上述机制经当前工作区依赖的 Warm-Flow **1.8.9** 源码 JAR 与前端包核对；展示效果来自 T1 浏览器报告。`FlowChart` 的 `id` 是实例 ID，不能传定义 ID；历史实例图不能用当前流程定义重绘。

**只读勘误**：本项目所带 1.8.9 UI 包中，`disabled=true` 主要限制保存及属性编辑，`onlyDesignShow=true` 控制设计页展示；设计画布仍挂载节点侧栏，LogicFlow 初始化没有因这两个参数启用静默模式，用户实测仍可加节点。实例 `FlowChart` 页也未显式启用静默模式。当前没有经证实可让两种入口完全只读的 URL 参数。后端写权限收口与画布交互只读是两件事；不得把“不能保存”当作“不能编辑图”。

## 3. 展示契约

1. 发起审批使用与“我的流程→查看”同类的抽屉容器；抽屉顶部参考角色管理页的线条式页签，设“申请内容”“流程图”两项，默认显示申请内容，同一时刻只展示一个页签的内容。流程图页签按需加载定义预览，离开时不影响已填写的表单；预览失败保留清晰错误状态，不把空白 iframe 当作成功，也不因预览失败改写表单提交权限。发起抽屉独立于实例详情 `DetailDrawer`，不复用其办理逻辑。
2. 待办、已办、我的流程共用的实例详情抽屉同样设“申请内容”“流程图”两个页签，默认显示申请内容；流程图页签按需加载实例运行图。“流程、实例 ID、状态、业务单据”四项概览置于页签上方，两个页签均可见；抽屉在窄视口不应被裁切。申请内容、审批意见和办理按钮继续由现有 `taskId` 逻辑决定：待办可办理，已办和我的流程只读；切换页签不丢失输入。旧 `TaskPanel.vue` 如重新启用，复用该抽屉即可，当前不为它虚构一个入口。
3. 实例图始终读取 `Instance.defJson` 保存的流程结构；运行状态以该实例的当前状态展示。审批后重新打开详情应重新拉取图。所有雪花 ID 在前端保持字符串。
4. 前端复用一个流程图组件，明确区分 `definition` 和 `instance` 模式，负责 URL、加载/失败状态、尺寸和卸载。两种模式都必须是画布交互只读：不得新增、拖动、删除或修改节点、连线；可保留缩放、平移、查看节点信息。只读接管未成功前不得暴露可交互画布；接管失败时应卸载或完全隔离 iframe 并显示失败状态，不能仅显示警告徽标。不能仅凭 iframe 的 `load` 事件判定业务接口成功，须有可验证的失败反馈。不要把 token、完整带 token 的 iframe URL 写入日志或验收截图文字。若 1.8.9 内置 UI 无稳定只读入口，先给出可验证的实现方案；不能仅隐藏保存按钮、依赖前端参数或用脆弱的样式遮挡冒充只读。
5. 实例图接口的可见范围与 `GET /admin/approval/instance/{id}` 一致。发起前预览只允许读取当前用户可发起的已发布、激活、绑定已发布表单的定义；有模型管理权限的用户可按其已有权限查看管理范围内的定义。不得仅靠前端传 `disabled=true` 控制写权限。

## 5. 验证与交付口径

- 本地前后端若已启动，先确认当前进程和配置；纯前端改动检查 HMR。Java 鉴权改动使用受控重启和真实响应确认生效，不能只凭 JRebel 热部署推断。
- 数据库查询使用 DBX `local-mysql-3306`，每次显式指定 `database=ibpm`。T1 优先复用已有定义/实例，不创建、清理或手改业务数据。
- 后端代码改动执行 `server/AGENTS.md` 要求的 `mvnw.cmd verify`；前端代码改动执行 `web/AGENTS.md` 要求的 `pnpm lint`、`pnpm typecheck`、`pnpm build`。构建通过不能代替浏览器和普通角色验收。
- 每项报告按“修改文件、通过项、未通过项、阻塞项、下一步”组织，注明静态核对、真实接口、真实浏览器和数据库各自的证据。未做的场景写“未验证”。
- 不因本任务修改已执行的 Liquibase changeset、角色授权或现有流程实例；若验证发现必须改变上述范围，先列明根因和最小变更方案，由主 Agent 决定下一个单项任务。
