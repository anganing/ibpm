IBPM 审批这块，现在做到哪了

采购单还在原来的系统里，审批可以交给 IBPM。

先用这句话介绍它吧。IBPM 接了 Warm-Flow 1.8.9，自己提供表单、流程管理和办理页面，也留了对外发起、查询的接口。有业务系统就走接口，没有的话，直接在它的审批页面填单也行。

配一条流程，大概会用到两个设计器。表单设计器里放申请内容，流程设计器里安排节点、选办理人。最后把表单绑上，发布。现在办理人选的是具体用户，部门主管这种跟组织关系走的选人方式，还没接。

用户进来能找到“我的待办”“我的已办”“我的流程”。待办里打开单据，填意见，通过或驳回；自己发起的则去“我的流程”找。详情是个抽屉，申请内容、流程图两个页签放在里面。

接口也会核对是不是本人该办的任务。只拿一个任务 ID 过来调用，不行。

这里我想多说两句表单。假如今天提了采购申请，明天管理员给表单加了字段，今天这张单再打开会怎样？IBPM 留了快照，申请当时的表单结构和数据一起存。详情读这份快照。所以“预计到货日期”哪怕后来成了必填项，也不该跑到老申请里，变成一个莫名其妙没填的空格。

看流程图时也要分清，它还不能代替逐步的审批意见记录。完整记录列表目前没有做到详情里。

版本管理这块倒不用绕。已经发布的流程点设计，会复制或复用下一版草稿；改完发布，旧版本保留。表单的已发布版本也不会直接拿来改。

流程上还有“暂停发起”。这个操作只挡新申请，之前提交的继续办。有时候某类业务暂停受理，关掉入口即可，没必要把已收的单子也卡住。

接原有系统，主要认准两个编号：业务单号和流程实例编号。前一个由业务系统传过来，后一个是 IBPM 发起成功后返回的，存好关联就行。发起请求还要带流程编码、发起人和表单数据。

字段名去哪找？流程管理里有“对接说明”，按当前生效流程绑定的表单解析字段，能填示例、复制请求 JSON 和 curl。中文叫“采购数量”，接口到底要传哪个键，看这里。尤其表格里有明细时，照着样例接方便一些。

状态可以主动查，外部应用也能配置回调地址，等流程结束后接通知。不过当前回调失败只记日志，没有自动重试。这个得提前告诉接入方，别只等通知，不查状态。

还有些功能先欠着。加签、减签、转办、委派已有方案，自己的页面和办理接口还没接。引擎支持是引擎的事，放到 IBPM 里能用，还得把这段做完。

这就是目前的范围。试用可以挑一张你们平时真要批的单，配表单、发起、处理，再回去找那张申请。接现有系统的，顺手把发起和查询也接一下。

比起先讨论能撑多少复杂场景，我更想先看到这张单在两边的状态对得上，申请人、审批人各自找得到入口。后面的需求，再一项项往上加。
