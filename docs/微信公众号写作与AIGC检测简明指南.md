# 微信公众号写作与 AIGC 检测简明指南

适用于项目介绍、功能说明类公众号文章。整理日期：2026-10-06。

本指南来自一次 IBPM 文章写作：前三版朱雀网页均显示“人工创作特征较弱”，第四版显示“人工创作特征显著”，人工特征 100%。没有逐项对照试验，以下是可复用的写作经验，不能保证其他文章得到相同结果。

## 1. 先把事实弄清楚

- 先看当前代码、页面和版本，旧文档只作线索。
- 分清已经实现、仅有设计、尚未验证的内容。引擎支持某功能，不代表项目已经接好。
- 示例明确写成示例，不编造客户案例、使用经历、运行效果或性能数字。
- 确定读者是谁。面向开发者可以写接口和字段；面向业务人员优先解释操作及结果。

## 2. 正文怎么写

- **从一件具体的事开始。** 比如“采购单保留在原系统，审批交给 IBPM”，让读者马上知道用途。
- **按实际使用顺序展开。** 配置、提交、办理、查看结果，再补版本调整或系统对接。结构随内容走，不必每篇套相同目录。
- **用细节支撑功能。** 写清入口名称、操作、数据如何关联。技术细节只放读者用得上的部分。
- **减少泛泛评价。** “提升效率”“强大灵活”“一站式赋能”可以删掉，换成实际行为。例如：“在对接说明中填写示例后，可以复制 JSON 请求体和 curl。”
- **说清楚就停。** 不给每段都补意义和总结，不刻意堆排比、反问、感叹或第一人称感想。
- **保留必要限制。** 影响选型和接入的边界简短交代，不把产品介绍写成完整审计报告。

本轮的提醒：第二、三版增加口语、缩短篇幅，仍未达到要求。第三版 1123 字符，第四版 1176 字符，说明“更短”“更口语”都不能单独当作有效方法。第四版增加了具体接入说明、减少评论性表达；这些变化与结果同时出现，不能据此认定因果。

## 3. 配图、检测与交付

1. 文章保存为 Markdown；需要配图的位置用有说明的占位链接：

   `![审批详情与流程图](https://example.com/replace-approval-detail.png)`

2. 提取**标题和全部正文**送检，可去掉图片占位及 Markdown 格式符号。保留精确文本副本，不挑选片段代替全文结论。
3. 用户指定网站时，在指定网站实测。接口结果与网页结果分别记录；接口鉴权失败不能当作检测成功。
4. 根据阅读问题修改，保持事实准确。保留各版文本、真实结果及最终截图，不添加无关内容、隐形字符或故意错字。
5. 检测后核对交付正文与送检副本一致。继续改正文，应重新检测；不能沿用旧结果。
6. 报告页面原文、显示占比和检测日期。检测值不等于作者身份，也不保证下一次复测相同。

```text
如结果未达要求，如实说明；最终正文必须与送检版本一致，不承诺未经验证的通过率。
```
